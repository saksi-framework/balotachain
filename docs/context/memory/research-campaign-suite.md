## Verified facts (checked in code 2026-07-21, not assumed)

- **Crypto is REAL, not stubs.** `saksi-crypto/src/nizk/cds.rs` is a genuine
  ristretto255 Chaum-Pedersen OR-proof with Fiat-Shamir challenge splitting;
  benaloh/chaum_pedersen/schnorr all use real group ops; saksi-credentials says
  "full implementations, not stubs". balotachain/CLAUDE.md's "all SHA-256 stubs"
  claim was STALE — corrected. What IS stubbed is *balotachain's demo credential
  material*, which is why balotachain ballots aren't chaincode-valid.
- **Generated ballots DO commit on the real chaincode** — balotachain `fabric` CI
  job runs `saksi-demo.sh gen` + `cycle` against a live network.
- **No MVCC hot key.** `SubmitBallot` reads statusKey/dkgKey/nullifierKey, writes
  only ballotKey+nullifierKey (unique per ballot). Concurrent submit and
  zero-drop Reconcile are compatible. Caveat: never CloseElection concurrently
  with submits (writes statusKey, which submits read).
- **Fixtures use `OsRng`** (fixtures.rs:88,363) → ballot bytes are NOT
  reproducible. Cross-language fixtures pin FORMAT, never generated bytes.
