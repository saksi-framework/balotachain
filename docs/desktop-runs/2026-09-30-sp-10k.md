## 5. Contention

The wizard marks a repetition **contended** when either of its two host samples (taken before generate and after verify) shows host CPU above 25 % or guest `load1` above 0.25 x 16 = 4.0. The two halves are reported separately here: **host** = a Windows host CPU sample over 25 %; **guest** = a WSL guest `load1` sample over 4.0. From 10K up the guest half is mostly the run's own generate and verify work (16 auditor threads) still in the 1-minute load average, not outside load.

Measured repetitions flagged: **10 of 10** by the wizard's rule; **host CPU: 0**, **guest load: 10** (a repetition can carry both). Highest host CPU sample on a measured repetition: 24.6 %.

Every measured repetition is flagged, **all on guest load** (load1 4.86 to 9.29); **host CPU never exceeded 25 %** on a measured repetition (maximum 24.6 %, m4 start). At 10K the guest's 1-minute load average is the run's own generate and verify work (16 auditor threads, about 1.8 s of in-process verification per repetition), sampled seconds after it. The guest half of the wizard's rule therefore flags every repetition from this tier up, whatever the host is doing: it cannot tell self-load from outside load. This is an instrument finding, reported in the study index.

## 8. Caveats

The host samples are two points per repetition (before generate, after verify), not a trace across the submission window: a spike between them is invisible, and a flagged sample can fall outside the window it is charged to. Host CPU is the Windows host's total. The desktop was not idle: at 01:52 local the study log recorded Docker Desktop's UI (about 1.3 cores), Brave (about 1.2 cores across its processes) and an `mpv` video player running, none started by the study. `ledger_bytes_delta` is empty in every run (no producer for the column on this path). One build, one machine, one single-orderer test network. `docs/CLAIMS.md` and `docs/manuscript-amendments.md` were not edited.
