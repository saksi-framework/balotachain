# AX42 (Hetzner): second study environment, setup report

Set up 2026-10-04 00:45–01:02 (Asia/Manila, the desktop's local time). The server runs the on-chain
MP tiers unattended: MP-1K (2 + 10), MP-10K (2 + 10), MP-50K (2 + 5), then MP-483K, MP-1M, MP-1.92M
and MP-3.5M, each as 1 warm-up + 3 measured single-rep campaigns on a freshly reset network.
Every election name carries `ax42` (`MP-1K ch4 ax42`, `MP-483K ch4 ax42 m1`, ...), so these runs never
pool with desktop runs.

## Orderer configuration (declared and verified by preflight)

`up.sh` / `tier.sh` bring the network up with saksi's `packages/saksi-bulletin/network/configtx.yaml`.
The console's preflight `orderer_batch` row on this server reads:
`MaxMessageCount 50`, `BatchTimeout 2s`, `PreferredMaxBytes 2 MB`, `AbsoluteMaxBytes 99 MB`,
`SnapshotIntervalSize 268435456` (256 MB), `saksi_configtx saksi`. The controller refuses to start a
run if any of these differ.

## Services

| Unit | What |
|---|---|
| `saksi-console.service` | `tools/up.sh` (which execs the console) on 127.0.0.1:8090, `SAKSI_PHASE_TIMEOUT=12h`, auth off (loopback only). Log `/root/ax42/console.log`. Started by the controller, not at boot |
| `ax42-controller.service` | `/root/ax42/controller.py`, enabled at boot, `Restart=on-failure` (60 s). Resumes from `/root/ax42/state.json`; after a reboot it starts Docker, `docker start`s the existing Fabric containers (no reset) and the console, then follows the power-cut policy (multi-rep campaign: redo from reset; single long run: resume, verify-only, trustees, publish, verify) |

The controller is a Linux port of the desktop's `C:\Users\User\ch4-capstone\controller.py`
(no WSL, no VHDX compaction: the reset wipes the ledger). Resource sampler every 10 s:
`docker stats` CPU / memory / block I/O per container, `/proc/meminfo`, loadavg, `iostat -dxyk 10`
for nvme0n1 / nvme1n1 / md2, `df /`, host CPU from `/proc/stat`, and the run's own CPU from its
cgroups (Docker container scopes, docker.service, containerd.service, saksi-console.service).
Non-run CPU = host CPU minus the run's CPU. Rerun rule: a measured run is rerun once only if non-run
CPU is above 25 % in more than 2 % of its ballot-window samples and in at least 6 of them.

Validation ladder on this build: `ladder-20261003-165827-1`, passed (4 runs,
commit 4a38a54), in [`2026-10-04-ax42-ladder/ladder.json`](2026-10-04-ax42-ladder/ladder.json).

First campaign: MP-1K `campaign-20261003-170017-3`, started 01:00; first windows committed

## Checking progress

One command, no analysis:

```
ssh -i ~/.ssh/hetzner_ax42 root@157.180.56.166 cat ~/ch4-ax42/STATUS.md
```

The controller rewrites `STATUS.md` before every step and after every run: queue position, results
so far (TPS, p99, max |E|, failed, contention samples), disk free, crashes, stop reason. More detail:
`~/ch4-ax42/study.md` (timestamped study-log lines), `~/ch4-ax42/controller.log`,
`systemctl status ax42-controller`. Hold the queue before the next step: `touch ~/ch4-ax42/STOP`
(a warm-up in progress is cancelled; a measured run finishes first).

## Evidence on the server

Everything stays on the server until one pull after the runs:

- `~/ch4-ax42/evidence/<n>-<label>/`: the unzipped export bundle (run.json, perf.csv, correctness.csv,
  journal, summary.csv, campaign.json, ...), resources.csv, resources-summary.txt, ledger-size.txt
  (`du` of the peer and orderer volumes), preflight, controller-log.txt, NOTE.md, the target path
  (`DEST`) and commit message (`MSG`); after a tier's last run also `TIERNOTE.md`.
- `~/ch4-ax42/work/<label>/logs/*.log.gz`: peer and orderer `docker logs`.
- `/root/.saksi/campaign/runs/<run>/ballots.ndjson.zst` and `ledger/ballots.ndjson.zst`, each with a
  `.sha256` sidecar holding the original's hash; `ballots.csv` deleted after the export.
  `~/ch4-ax42/archive.tsv` lists every archive file with its sha256 and size.

## Pulling the evidence

From the desktop, after the queue completes (`complete:` set in STATUS.md):

```
python C:\Users\User\ax42-pull\pull.py
```

repeated until `python C:\Users\User\ax42-pull\pull.py status` shows every outbox entry and every
archive file. Each cycle: study-log lines into `ch4-study-log.md` (section "AX42 (Hetzner), 2026-10-04 →"),
each evidence folder into `docs/desktop-runs/2026-10-04-ax42-<tier>/...` with a commit and push on
`docs/ch4-night1-2026-10-01`, then the `.zst`, `.sha256` and log files into
`Q:\thesis-archive\ax42\<run>\`, each sha256-checked against the server's hash (a mismatch is
deleted and retried). It holds an archive file if Q: would drop below 20 GB free.
**Q: needs room:** the raw files for all 16 large-tier runs are estimated at about 300 GB
compressed. Cancel the server only after `status` shows every archive file.
